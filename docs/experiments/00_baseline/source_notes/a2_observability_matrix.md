## Cache-specific findings

`rv64im_core_dcache.sv:113-119` defines `req_vld` as
`i_mem_req_vld & o_mem_req_rdy`, then derives one-cycle combinational
`req_hit`/`req_miss` from the accepted address. `state_is_wbus` and
`state_is_rbus` persist refill/writeback state; `wbus_done` and `rbus_done`
are completion pulses based on bus handshakes and four 64-bit banks. Thus a
miss count must use accepted `req_miss`, while wait cycles use state/handshake
occupancy. `o_mem_req_rdy` is blocked by non-NORM state and response stall
(`rv64im_core_dcache.sv:490-492`). I-cache requests can include wrong-path
fetches because IFU flush invalidates returned data only after fetch activity;
D-cache architectural attribution remains unproven until retirement/LSU
alignment is validated.

## Branch and system findings

IFU prediction is generated by `dirbrn_pt` (`rv64im_core_ifu.sv:49-67`) using
the saturating counter and optional RAS. EXU resolves `jump_res` and target
(`rv64im_core_alu.sv:248-293`). Under `SAT_CNT`, `cond_err` is direction
mismatch and `jalr_err` is an indirect-target mismatch with RAS; without that
configuration `o_alu_flush` uses `jump_flag`. Interrupt/exception and `mret`
share the pipeline flush path through `rv64im_core_intr_ctrl.sv:33-53` and
`rv64im_core_pipe_ctrl.sv:25-31`. Therefore generic flush is not a branch
mispredict count, and JAL/JALR inclusion in `branch_count` must be fixed by
the metric contract rather than inferred from `bflush_num`.
