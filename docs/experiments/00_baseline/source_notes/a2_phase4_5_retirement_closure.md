# A2 Phase 4.5 Retirement-Event Closure

## Question and decision

Can A2 expose an architectural retirement/commit event suitable for performance normalization? **No.** The final classification remains **PARTIAL_RETIREMENT_EVENT**.

`wb_sign` is a useful simulation/DiffTest observation boundary, but it is not generated from an explicit pipeline valid/non-killed commit condition. The existing Phase 4 directed evidence validates only its listed instruction subset.

## `wb_sign` source trace

[RTL] `rv64im_core_sim_top.sv:85-122` obtains `exu_pc` and `exu_inst` through simulation-only hierarchy references to the ALU input. When `pipe_wbu_stall` is low, wrapper registers shift `exu_pc` through `mem_pc` then `wbu_pc`, and shift instruction through `mem_inst` then `wbu_inst`.

```
wb_sign = wb_start | (wb_buff & (wbu_pc != 0) & !wb_wait)
```

`wb_start` is `mem_pc == 64'h80000004`; `wb_buff` becomes one at that condition and has no reset/clear assignment in its process. Thus `wb_sign` is not generated by `rv64im_core_wbu` or `rv64im_core_wb`.

[RTL] `rv64im_core_wbu.sv:18-34` holds only destination index, destination write enable, and result data. Its reset is `!rstn | i_wbu_flush`; it has no instruction-valid, PC-valid, kill, or commit output. `rv64im_core_wb.sv` is combinational pass-through. No existing internal condition equivalent to `WB_valid && !WB_killed` was found.

[RTL] Invalid fetches and flushes become NOP/zero-PC data upstream (`rv64im_core_ifu.sv:183-186`, `rv64im_core_if_id.sv:15-18`, and `rv64im_core_id_alu.sv:30-41`), but no valid bit is carried with the wrapper's delayed PC/instruction. `rv64im_core_pipe_ctrl.sv:20-27` separately masks redirect, interrupt, and dependency flushes. The wrapper therefore cannot structurally prove that every nonzero delayed PC is one non-killed architectural instruction.

Consequences: reset is suppressed only incidentally by initialized wrapper PCs and `wb_buff`; bubbles may be represented as zero-PC/NOP data but no wrapper valid bit proves exclusion in every timing case; wrong-path instructions are killed upstream but no kill relation qualifies `wb_sign`; stores and non-link branches cannot use `rd_wen` as a retirement proxy; and the asynchronous-interrupt `mem_pc` zeroing plus `intr_buff` is DiffTest protocol support, not commit state.

## DiffTest relationship

[C++] `sim/csrc/sim_main.cpp:237-263` calls `difftest_step()` once for each `wb_sign` after the first observation (`wb_num != 0`). `sim/csrc/difftest.cpp:63-71` either advances NEMU by exactly one instruction with `ref_difftest_exec(1)`, or, after a device-tagged event, copies DUT register state to the reference and clears the skip flag. Thus one call is not always one reference instruction advance.

[C++] For `wb_intr`, the harness advances/checks the preceding reference instruction, then injects `intr_num`. `wb_intr` is derived from wrapper state and an `mtvec` PC match (`rv64im_core_sim_top.sv:125-136`); it is not another retired instruction. `wb_device` requests a one-step reference skip for the next event. DiffTest success establishes compatibility of this protocol with the exercised execution, not a universal commit proof: the first event is not stepped, devices substitute state synchronization, and no valid/kill state drives `wb_sign`.

## Validation and stop condition

[MEASURED] `make doctor`, `make build -j1`, the targeted runner, `make run TEST=dummy`, and `make smoke` passed. The first direct runner attempt was rejected only because its tracked mode is non-executable; running the same content through `bash` passed. No simulation-top or observer source changed, so full regression was not rerun; Phase 4's recorded full regression remains the integration baseline.

The source trace plus this one targeted round does not establish a commit-qualified event. Per the Phase 4.5 stop condition, work ends here without pipeline redesign or new instrumentation.
